# Phase 2 — ค้นหา/เลือกผู้ป่วย + การป้องกันข้อมูลพื้นฐาน + AI อธิบายผลค้นหา: งานย่อย

ส่วนหนึ่งของ [[release-plan]] (Phase 2) ครอบคลุม FR-05, FR-06, FR-17, NFR-02, NFR-03, NFR-04, NFR-06,
NFR-21 จาก [[backlog]] รวมส่วนพื้นฐานของ [[feature-list#3. ค้นหา/เลือกผู้ป่วย|feature-list ฟีเจอร์ที่ 3]]
และส่วนพื้นฐานของ [[feature-list#4. คุ้มครองข้อมูลส่วนบุคคลของผู้ป่วยตาม PDPA|feature-list ฟีเจอร์ที่ 4]]
งานย่อยด้านล่างเขียนด้วยภาษาเชิงพฤติกรรม/ผลลัพธ์เท่านั้น **ไม่ระบุเทคโนโลยีการ implement**
ต้องเริ่มหลัง [[phase-1-authentication-tasks|Phase 1]] เสร็จสมบูรณ์ (ผู้ใช้งานต้องเข้าสู่ระบบและยืนยัน
อีเมลสำเร็จก่อนจึงจะเริ่ม journey นี้ได้)

**หมายเหตุอัปเดต 2026-09-28:** (1) ระบบยกเลิกกลไก PatientAssignment ทั้งหมดตั้งแต่ 2026-09-25 — ทุก
บทบาท (แพทย์/พยาบาล/admin) ที่ผ่านเงื่อนไขพื้นฐาน (เข้าสู่ระบบสำเร็จ, ยืนยันอีเมลแล้ว, บทบาทที่ระบบ
อนุญาต, บัญชียังใช้งานอยู่) เห็น**ผู้ป่วยทุกรายในระบบเหมือนกัน** ไม่มีการจำกัดตามการมอบหมายรายผู้ป่วย
อีกต่อไป T-2-01/T-2-04 ด้านล่างแก้ถ้อยคำให้ตรงกับนิยามนี้แล้ว และไม่มี dependency กับ Phase 1 อีกต่อไป
(เดิมเคยพึ่ง T-1-12/FR-14 ซึ่งถูกตัดออกจากแผนแล้ว) (2) เพิ่ม T-2-08/T-2-09 (FR-17, NFR-21 — รหัสใหม่
จาก requirement ดิบเรื่อง AI ช่วยอธิบายผลการค้นหา) เป็นส่วนขยายโดยตรงของ T-2-02/T-2-03 (FR-06)

| รหัส | ชื่องาน | FR/NFR ที่เกี่ยวข้อง | หมายเหตุ dependency ภายใน phase |
| --- | --- | --- | --- |
| T-2-01 | แพทย์/พยาบาล/admin เรียกดูรายชื่อผู้ป่วย NCD ทุกรายในระบบ (ไม่จำกัดตามการมอบหมายรายบุคคล) | FR-05 | ไม่มี — เป็นจุดเริ่มต้นของ phase |
| T-2-02 | ค้นหาผู้ป่วยเฉพาะรายด้วยเลขประจำตัวผู้ป่วย (HN) รูปแบบตัวเลขล้วน 7 หลัก ทั้งตอนหยุดพิมพ์ชั่วขณะ (debounce) และตอนกดปุ่มค้นหา | FR-06 | ต่อจาก T-2-01 |
| T-2-03 | แจ้งเตือนผู้ใช้เมื่อกรอก HN ไม่ครบ 7 หลัก หรือค้นหาด้วย HN ที่ครบ 7 หลักแล้วแต่ไม่พบผู้ป่วยที่ตรงกัน (ตรวจได้ทั้งตอนหยุดพิมพ์และตอนกดค้นหา) โดยให้กรอกค้นหาใหม่ได้ทันทีและไม่บล็อกการเรียกดูรายชื่อทั้งหมด | FR-06 | ต่อจาก T-2-02 |
| T-2-04 | จำกัดไม่ให้ผู้ใช้งานที่ไม่ผ่านเงื่อนไขพื้นฐาน (ยังไม่เข้าสู่ระบบ, ยังไม่ยืนยันอีเมล, บทบาทที่ระบบไม่อนุญาต, บัญชีถูกระงับ) เห็น/เข้าถึงข้อมูลผู้ป่วยใดๆ ได้ — ผู้ใช้ที่ผ่านเงื่อนไขครบทุกคนเข้าถึงผู้ป่วยทุกรายเท่ากัน ไม่มีการจำกัดระดับรายผู้ป่วยอีกต่อไป | NFR-02 | ต่อจาก T-2-01 |
| T-2-05 | จำกัดการประมวลผลข้อมูลผู้ป่วยเฉพาะเท่าที่จำเป็นต่อวัตถุประสงค์การดูแลรักษาเท่านั้น ในทุกจุดที่ระบบเข้าถึงข้อมูลผู้ป่วย | NFR-03 | ต่อจาก T-2-01, T-2-04 |
| T-2-06 | เข้ารหัสข้อมูลผู้ป่วยทั้งขณะจัดเก็บและขณะส่งผ่านเครือข่ายในทุกจุดที่ข้อมูลผู้ป่วยไหลผ่าน | NFR-04 | ต่อจาก T-2-01 |
| T-2-07 | บันทึกร่องรอยการเข้าถึงข้อมูลผู้ป่วย (ใครเข้าถึง/เมื่อไร/ข้อมูลใด) ทุกครั้งแบบไม่มีการยกเว้น แม้การบันทึกจะล้มเหลวก็ต้องไม่ปล่อยให้เข้าถึงข้อมูลได้โดยไม่มีร่องรอย (fail-safe) | NFR-06 | ต่อจาก T-2-04 |
| T-2-08 | เมื่อผู้ใช้กดปุ่มค้นหาด้วย HN (ไม่ใช่ตอนหยุดพิมพ์) เรียกบริการ AI ภายนอกช่วยอธิบายผลการค้นหาเป็นภาษาคนประกอบผลลัพธ์ที่แสดงอยู่แล้ว ครอบคลุม 3 กรณี (พบผู้ป่วย/ไม่พบผู้ป่วย/กรอก HN ไม่ครบ 7 หลัก) พร้อมป้ายกำกับชัดเจนว่าเป็นข้อมูลประกอบ ไม่ใช่คำแนะนำทางการแพทย์ — หากบริการ AI ใช้งานไม่ได้/ล้มเหลว การค้นหาปกติ (T-2-02/T-2-03) ต้องยังใช้งานได้ตามปกติ ไม่ถูกบล็อก | FR-17 | ต่อจาก T-2-02, T-2-03 |
| T-2-09 | จำกัดข้อมูลที่ส่งให้บริการ AI ภายนอกตาม T-2-08 ให้เหลือเฉพาะเลข HN ที่ผู้ใช้พิมพ์และผลการค้นหาแบบไม่ระบุตัวตน (สถานะพบ/ไม่พบ/HN ไม่ครบหลัก, จำนวนที่พบ) ห้ามส่งชื่อผู้ป่วยหรือข้อมูลระบุตัวตนใดๆ ให้บริการ AI เด็ดขาด | NFR-21 | ต่อจาก T-2-08 (บังคับใช้ทุกครั้งที่เรียก AI) |
