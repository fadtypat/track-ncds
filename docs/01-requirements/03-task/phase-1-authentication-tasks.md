# Phase 1 — Authentication & Account Administration: งานย่อย

ส่วนหนึ่งของ [[release-plan]] (Phase 1) ครอบคลุม FR-07–FR-10, FR-11–FR-14, NFR-17, NFR-18 จาก
[[backlog]] รวม [[feature-list#6. สมัครบัญชี เข้าสู่ระบบ และจัดการรหัสผ่านด้วยอีเมล (Authentication)|feature-list ฟีเจอร์ที่ 6]]
ทั้งหมด และส่วนจัดการบัญชี/role/มอบหมายผู้ป่วยของ
[[feature-list#7. จัดการบัญชีผู้ใช้งาน สิทธิ์ และการมอบหมายผู้ป่วย (Admin)|feature-list ฟีเจอร์ที่ 7]]
(เฉพาะ FR-11–FR-14 — ส่วน FR-15/NFR-19/NFR-20 ของฟีเจอร์เดียวกันอยู่ที่
[[phase-4-complication-risk-analysis-alerting-tasks|Phase 4]] เพราะต้องพึ่งข้อมูลวินิจฉัย/lab/ความเสี่ยง
ที่ยังไม่มีใน Phase นี้) งานย่อยด้านล่างเขียนด้วยภาษาเชิงพฤติกรรม/ผลลัพธ์เท่านั้น **ไม่ระบุเทคโนโลยีการ
implement**

**หมายเหตุอัปเดต 2026-09-24 (รอบสอง):** T-1-01–T-1-08 (FR-07–FR-10, NFR-17, NFR-18) ถูก implement
เป็นโค้ดแล้วและ merge แล้วก่อนรอบนี้ โดยผู้ดูแลระบบแก้ไขข้อมูลบัญชีโดยตรงนอกหน้าจอของระบบ (ชั่วคราว) แทน T-1-09
(FR-11) ที่เพิ่งเพิ่มเข้ามา — T-1-09–T-1-12 ด้านล่างจึงเป็นงานเพิ่มเติมที่ต้อง implement ต่อจากโค้ดเดิม
ไม่ใช่แผนที่ยังไม่เริ่มทำ

| รหัส | ชื่องาน | FR/NFR ที่เกี่ยวข้อง | หมายเหตุ dependency ภายใน phase |
| --- | --- | --- | --- |
| T-1-01 | ผู้ใช้งานสมัครบัญชีใหม่ด้วยตนเองโดยกรอกอีเมลและรหัสผ่าน | FR-08 | ไม่มี — เป็นจุดเริ่มต้นของ phase |
| T-1-02 | บัญชีที่สมัครใหม่อยู่ในสถานะยังใช้งานไม่ได้ (ไม่มีสิทธิ์/บทบาทใดๆ) จนกว่าผู้ดูแลระบบจะอนุมัติสิทธิ์ให้ | FR-08 | ต่อจาก T-1-01 |
| T-1-03 | บังคับให้รหัสผ่านที่ผู้ใช้ตั้งตอนสมัครมีความยาวขั้นต่ำ 8 ตัวอักษร และมีทั้งตัวอักษรและตัวเลข | NFR-17 | ต่อจาก T-1-01 (ตรวจสอบระหว่างขั้นตอนสมัคร) |
| T-1-04 | ระบบส่งอีเมลยืนยันตัวตนให้ผู้สมัครใหม่ทันทีหลังสมัครสำเร็จ | FR-09 | ต่อจาก T-1-01 |
| T-1-05 | บล็อกไม่ให้ผู้ใช้ที่ยังไม่ยืนยันอีเมลเข้าใช้งานฟีเจอร์อื่นของระบบ พร้อมแจ้งเตือนให้ยืนยันก่อน | FR-09 | ต่อจาก T-1-04 |
| T-1-06 | ผู้ใช้งานที่มีบัญชีอยู่แล้ว (ผ่านการอนุมัติและยืนยันอีเมลแล้ว) เข้าสู่ระบบด้วยอีเมลและรหัสผ่านได้สำเร็จ | FR-07 | อิสระจาก T-1-01–05 (ใช้บัญชีที่มีอยู่แล้ว) |
| T-1-07 | ผู้ใช้งานที่ลืมรหัสผ่านขอลิงก์รีเซ็ตรหัสผ่านทางอีเมล และตั้งรหัสผ่านใหม่ได้สำเร็จตามนโยบายความซับซ้อนขั้นต่ำเดียวกัน | FR-10, NFR-17 | อิสระจาก T-1-01–06 |
| T-1-08 | ทุกขั้นตอน (เข้าสู่ระบบผิดพลาด, สมัครด้วยอีเมลที่มีอยู่แล้ว, ขอรีเซ็ตรหัสผ่านด้วยอีเมลที่ไม่มีในระบบ) แสดงข้อความแจ้งเตือนแบบเดียวกันเสมอ โดยไม่เปิดเผยว่าอีเมลที่กรอกมีบัญชีอยู่ในระบบหรือไม่ | NFR-18 | ต่อจาก T-1-01, T-1-06, T-1-07 (ครอบคลุมทั้ง 3 ขั้นตอน) |
| T-1-09 | ผู้ดูแลระบบ (Admin) เปิดดูรายการบัญชีที่สมัครใหม่และรออนุมัติ แล้วอนุมัติบัญชีพร้อมกำหนดบทบาท (แพทย์/พยาบาล) ให้ใช้งานได้ทันที ผ่านหน้าจอในระบบ (แทนที่การแก้ไขข้อมูลบัญชีโดยตรงนอกหน้าจอของระบบที่เคยใช้ชั่วคราว) | FR-11 | ต่อจาก T-1-01–T-1-05 (บัญชีต้องยืนยันอีเมลก่อนจึงปรากฏในคิวรออนุมัติ) |
| T-1-10 | ผู้ดูแลระบบเปลี่ยนบทบาทของผู้ใช้งานที่เคยอนุมัติแล้ว ผ่านหน้าจอในระบบ | FR-12 | ต่อจาก T-1-09 (ต้องมีบัญชีที่อนุมัติแล้วก่อน) |
| T-1-11 | ผู้ดูแลระบบระงับการใช้งานบัญชีผู้ใช้งาน (ทำให้เข้าถึงข้อมูลผู้ป่วยใดๆ ไม่ได้ทันที) และเปิดใช้งานบัญชีที่เคยถูกระงับกลับมาใช้งานได้อีกครั้ง | FR-13 | ต่อจาก T-1-09 |
| T-1-12 | ผู้ดูแลระบบมอบหมาย/ยกเลิกการมอบหมายผู้ป่วยรายบุคคลให้แพทย์/พยาบาลที่มีบัญชีใช้งานได้แล้ว ผ่านหน้าจอในระบบ | FR-14 | ต่อจาก T-1-09 (ต้องมีบัญชีแพทย์/พยาบาลที่อนุมัติแล้วก่อนจึงมอบหมายผู้ป่วยให้ได้) — **เป็น dependency บังคับของ Operation "เรียกดูรายชื่อผู้ป่วยในความดูแล" ใน [[phase-2-patient-search-selection-data-protection-foundation-tasks|Phase 2]]** (ปัจจุบันไม่มีวิธีอื่นสร้าง PatientAssignment ในระบบ) |
