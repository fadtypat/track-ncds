NCDS CLINIC · HOSXP INTEGRATION DEMO — CLICKABLE PROTOTYPE

ประวัติโรค NCD ผลตรวจ Lab และการวิเคราะห์ความเสี่ยงโรคแทรกซ้อน

Prototype เวอร์ชัน v1 ของฟีเจอร์ตาม 20260917-01-patient-ncd-history-lab-complication-risk, 20260921-01-pdpa-data-protection-compliance, 20260923-01-user-authentication-email-password และ 20260924-01-admin-role-account-management ครอบคลุมฟีเจอร์ Must have ใน feature-list.md สำหรับผู้ใช้ 2 บทบาท: แพทย์/พยาบาลผู้ดูแลผู้ป่วย NCD และ Admin (ผู้ดูแลระบบ) (อัปเดต 20260924: เพิ่มฟีเจอร์ที่ 6 — สมัครบัญชี/เข้าสู่ระบบ/จัดการรหัสผ่านด้วยอีเมล เป็น precondition ก่อน Journey ที่ 1 และ 2 ด้านล่าง, เพิ่มฟีเจอร์ที่ 7 — Admin อนุมัติบัญชี/จัดการสิทธิ์/ มอบหมายผู้ป่วย/ดูประวัติผู้ป่วยทุกรายแบบอ่านอย่างเดียว และเพิ่ม FR-16 — ยืนยัน/แก้ไขผลประเมิน ความเสี่ยงในหน้าประวัติ+ความเสี่ยงของแพทย์/พยาบาล)

บทบาทผู้ใช้: แพทย์/พยาบาลผู้ดูแลผู้ป่วย NCD (NFR-02) บทบาทผู้ใช้: Admin ผู้ดูแลระบบ (NFR-19, NFR-20)

Journey ที่ 0 — สมัครบัญชี เข้าสู่ระบบ และจัดการรหัสผ่านด้วยอีเมล (Authentication, ฟีเจอร์ 6)

Precondition ก่อน Journey ที่ 1 และ 2 ทั้งหมด — ต้องเข้าสู่ระบบและยืนยันอีเมลสำเร็จก่อนจึงเริ่มดูข้อมูลผู้ป่วยได้
  1. 1. สมัครบัญชีใหม่ด้วยอีเมล/รหัสผ่าน แสดงกฎรหัสผ่านขั้นต่ำแบบ live · บัญชีใหม่ isActive=false ไม่มี role จนกว่าผู้ดูแลระบบจะอนุมัติ
    เปิดหน้าสมัครบัญชี FR-08·NFR-17·NFR-18
  2. 2. ยืนยันอีเมล / รอ Admin อนุมัติบัญชีผ่านหน้าจอในระบบ สาธิตทั้งสถานะ "ส่งอีเมลยืนยันแล้ว" และ "ยืนยันสำเร็จ รอ Admin อนุมัติผ่านหน้าจอในระบบ (FR-11, ดู Journey ที่ 3)"
    เปิดหน้ายืนยันอีเมล FR-09
  3. 3. เข้าสู่ระบบด้วยอีเมล/รหัสผ่าน กรณีผิดพลาด/ยังไม่ยืนยันอีเมล/สำเร็จ — ข้อความผิดพลาดเป็นแบบทั่วไปเสมอ ไม่เปิดเผยว่าอีเมลมีในระบบหรือไม่
    เปิดหน้าเข้าสู่ระบบ FR-07·NFR-18
  4. 4. ลืมรหัสผ่าน → ตั้งรหัสผ่านใหม่ ขอลิงก์รีเซ็ตทางอีเมล (ข้อความเดียวกันเสมอ) แล้วตั้งรหัสผ่านใหม่ตามนโยบายขั้นต่ำ
    เปิดหน้าลืมรหัสผ่าน FR-10·NFR-18 เปิดหน้าตั้งรหัสผ่านใหม่ FR-10·NFR-17

Journey ที่ 1 — routine การดูแลผู้ป่วย (ฟีเจอร์ 1–3)

อ้างอิง user-journey.md — ลำดับ: ตรวจสิทธิ์ → ค้นหา/เลือกผู้ป่วย → ดูประวัติ+lab → วิเคราะห์ความเสี่ยง
  1. 1. ระบบตรวจสอบสิทธิ์การเข้าถึง ถ้าไม่มีสิทธิ์ หรือผู้ป่วยไม่ได้อยู่ในความดูแล → ปฏิเสธการเข้าถึง
    เปิดหน้าปฏิเสธการเข้าถึง NFR-02
  2. 2. ค้นหา/เลือกผู้ป่วยในความดูแล ค้นหาด้วยเลข HN 7 หลัก หรือเรียกดูรายชื่อทั้งหมดที่อยู่ในความดูแล
    เปิดหน้ารายชื่อผู้ป่วย FR-05·FR-06
  3. 3. ดูประวัติวินิจฉัย + ผลตรวจ lab ย้อนหลัง + ผลวิเคราะห์ความเสี่ยง (พบความเสี่ยง) ตัวอย่างผู้ป่วยที่ระบบ flag ความเสี่ยงโรคแทรกซ้อนสูง/สูงมาก
    เปิดตัวอย่าง (พบความเสี่ยง) FR-01·FR-02·FR-03·FR-04
  4. 3b. ดูประวัติวินิจฉัย + ผลตรวจ lab ย้อนหลัง + ผลวิเคราะห์ความเสี่ยง (ไม่พบความเสี่ยง) ตัวอย่างผู้ป่วยที่ไม่พบความเสี่ยงเกิน threshold — แขนง "ไม่พบ" ของ FR-04
    เปิดตัวอย่าง (ไม่พบความเสี่ยง) FR-01·FR-02·FR-03·FR-04

Journey ที่ 2 — คำขอใช้สิทธิของเจ้าของข้อมูล และสนับสนุนการสืบสวนข้อมูลรั่วไหล (PDPA, ฟีเจอร์ 4)

Trigger จากเหตุการณ์ภายนอก (ไม่ใช่ routine การดูแลผู้ป่วย) — แยก 2 เส้นทางตามประเภทเหตุการณ์
  1. 2ก. ได้รับคำขอใช้สิทธิของเจ้าของข้อมูล (ผู้ป่วย) ค้นหาผู้ป่วยด้วย HN (Operation 0, ใช้หน้าค้นหา/รายชื่อผู้ป่วยร่วมกัน) → เลือกประเภทคำขอ (เข้าถึง/สำเนา/แก้ไข/ลบ/คัดค้าน) → ดำเนินการ
    เปิดหน้าคำขอใช้สิทธิ PDPA NFR-03·NFR-05·NFR-06·NFR-07
  2. 2ข. สงสัยว่ามีเหตุข้อมูลส่วนบุคคลรั่วไหล สืบค้น audit log (ระบุผู้ป่วย/ช่วงเวลา/ผู้ใช้ — ไม่บังคับ) เพื่อสนับสนุนการสืบสวน/แจ้งเหตุละเมิด
    เปิดหน้าสืบค้น audit trail NFR-02·NFR-06·NFR-08

Journey ที่ 3 — Admin อนุมัติบัญชี จัดการสิทธิ์ และดูประวัติผู้ป่วยทุกรายแบบอ่านอย่างเดียว (ฟีเจอร์ 7)

บทบาทใหม่: Admin (ผู้ดูแลระบบ) — เข้าสู่ระบบด้วยกลไกเดียวกับแพทย์/พยาบาล (FR-07) แต่มีสิทธิ์ต่างออกไป · งานบริหารจัดการ 4 อย่าง ทำทีละงานแล้ววนกลับมาเลือกงานอื่นต่อได้
  1. 3ก. อนุมัติบัญชีผู้ใช้งานใหม่ ดูรายชื่อบัญชีที่รออนุมัติ กำหนด role (แพทย์/พยาบาล) และเปิดใช้งาน — แทนที่กลไก Firebase Console/Firestore เดิม
    เปิดหน้าอนุมัติบัญชี FR-11
  2. 3ข. เปลี่ยนบทบาท / ระงับ-เปิดใช้งานบัญชี จัดการผู้ใช้งานที่เคยอนุมัติแล้วทั้งหมด
    เปิดหน้าจัดการผู้ใช้งาน FR-12·FR-13
  3. 3ค. จัดการการมอบหมายผู้ป่วย (Patient Assignment) มอบหมาย/ยกเลิกการมอบหมายผู้ป่วยให้แพทย์/พยาบาล — ควบคุมการมองเห็นผู้ป่วยตาม FR-05
    เปิดหน้ามอบหมายผู้ป่วย FR-14
  4. 3ง. ดูประวัติผู้ป่วยทุกรายในระบบ (อ่านอย่างเดียว) ไม่ต้องมี PatientAssignment เป็นของตนเอง (NFR-19) ทุกครั้งที่เข้าถึงต้องบันทึก audit log แบบ fail-safe ก่อนเสมอ (NFR-20)
    เปิดหน้าผู้ป่วยทุกราย FR-15·NFR-19 เปิดตัวอย่างหน้ารายละเอียด FR-15·NFR-20
  5. 3จ. เมนูหลักของ Admin หน้ารวมทางเข้าสู่ทั้ง 4 งานข้างต้น เข้าถึงหลัง Admin เข้าสู่ระบบสำเร็จ (FR-07)
    เปิดแผงควบคุม Admin FR-11–FR-15
