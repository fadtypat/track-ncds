แผงควบคุมผู้ดูแลระบบ (Admin)

Admin เป็นบทบาทใหม่ (role ที่ 3 ควบคู่แพทย์/พยาบาล) มีสิทธิ์อนุมัติบัญชี เปลี่ยนบทบาท ระงับ/เปิด ใช้งานบัญชี มอบหมายผู้ป่วย และดูประวัติผู้ป่วยทุกรายแบบอ่านอย่างเดียวผ่านหน้าจอในระบบ (FR-11–FR-15) — ไม่มีสิทธิ์แก้ไขข้อมูลทางคลินิกใดๆ สิทธิ์ยืนยัน/แก้ไขผลวิเคราะห์ความเสี่ยงยังคงเป็นของแพทย์/ พยาบาลเท่านั้น (FR-16)

บทบาท: Admin — เข้าถึงผู้ป่วยทุกรายโดยไม่ต้องมี PatientAssignment (NFR-19)

ผู้ป่วยทั้งหมดในระบบ 6 คน

เลือกงานที่ต้องการดำเนินการ

ทำทีละงานแล้ววนกลับมาเลือกงานอื่นต่อได้ (ไม่ใช่ flow เชิงเส้น) ตาม user-journey
  1. 1. อนุมัติบัญชีผู้ใช้งานใหม่ ดูรายชื่อบัญชีที่สมัครเองแล้วรอการอนุมัติ กำหนด role (แพทย์/พยาบาล) และเปิดใช้งาน
    เปิดหน้าอนุมัติบัญชี FR-11
  2. 2. เปลี่ยนบทบาท / ระงับ-เปิดใช้งานบัญชี จัดการผู้ใช้งานที่เคยอนุมัติแล้วทั้งหมด
    เปิดหน้าจัดการผู้ใช้งาน FR-12·FR-13
  3. 3. จัดการการมอบหมายผู้ป่วย มอบหมาย/ยกเลิกการมอบหมายผู้ป่วยรายบุคคลให้แพทย์/พยาบาล (patientAssignments)
    เปิดหน้ามอบหมายผู้ป่วย FR-14
  4. 4. ดูประวัติผู้ป่วยทุกรายในระบบ (อ่านอย่างเดียว) ไม่ต้องมี PatientAssignment เป็นของตนเอง ทุกครั้งที่เข้าถึงต้องบันทึก audit log แบบ fail-safe ก่อนเสมอ
    เปิดหน้าผู้ป่วยทุกราย FR-15·NFR-19
ขอบเขตสิทธิ์ของ Admin

Admin ไม่มีสิทธิ์แก้ไขข้อมูลทางคลินิกใดๆ (ประวัติวินิจฉัย, ผล lab, ผลวิเคราะห์ความเสี่ยง) สิทธิ์ ยืนยัน/แก้ไข (override) ผลวิเคราะห์ความเสี่ยงยังคงเป็นของแพทย์/พยาบาลผู้ดูแลผู้ป่วยรายนั้นเท่านั้น (FR-16) การสร้างบัญชี Admin คนแรก (bootstrap) ยังคงดำเนินการผ่าน Firebase Console/Firestore โดยตรง อยู่นอกขอบเขตของหน้าจอนี้

Audit log แบบ fail-safe (NFR-20)

ทุกครั้งที่ Admin เข้าถึงข้อมูลผู้ป่วยรายบุคคลตาม FR-15 ระบบต้องบันทึก audit log ก่อนคืนข้อมูลเสมอ หากบันทึกไม่สำเร็จ ระบบต้องปฏิเสธการเข้าถึงข้อมูลผู้ป่วยรายนั้นทันที — ดูตัวอย่างที่หน้า "ดูประวัติ (read-only)"
