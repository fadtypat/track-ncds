## ขอบเขตการทดสอบรอบนี้

ทดสอบเฉพาะ 2 test case ตามที่ผู้ประสานงานระบุ:
- TC-03-06 (FR-06 AC-3) — HN = `HN0123A`
- TC-03-07 (FR-06 AC-4) — HN = `9999999`

ก่อนเริ่ม ตรวจสอบรายชื่อผู้ป่วยทั้งหมด (30 คน) บนหน้าจอด้วย browser_snapshot แล้วยืนยันว่าไม่มี HN
`9999999` อยู่ในรายชื่อจริง จึงใช้ค่านี้ตามที่ระบุในเอกสารได้โดยไม่ต้องเปลี่ยนเลข

ปฏิบัติตามกฎโหมด "คนล็อกอินให้แล้ว" ครบถ้วน: ไม่กรอกรหัสผ่าน ไม่กดออกจากระบบ ไม่กดปุ่ม
"เพิ่มผู้ป่วยจำลองสำหรับทดสอบ" ไม่เข้า `/admin/approvals` ใช้แท็บเดิมตลอด ไม่ปิดเบราว์เซอร์ ไม่นำอีเมล
ของบัญชีทดสอบหรือชื่อ/HN ของผู้ป่วยในรายชื่อมาใส่ในรายงานฉบับนี้ (ยกเว้น HN ที่เป็น Test Data
ตามเอกสารเอง คือ `HN0123A` และ `9999999` ซึ่งไม่ตรงกับผู้ป่วยรายใดในระบบ)

## ข้อสังเกตอื่น

- Console error ที่ไม่ผูกกับ TC ใดโดยตรง: พบ error ซ้ำ 3 ครั้งในทั้งสอง TC
  `Failed to load resource: the server responded with a status of 400 ()` จาก
  `https://content-firebaseappcheck.googleapis.com/.../exchangeRecaptchaV3Token` — เป็นความล้มเหลวของ
  การแลกเปลี่ยน App Check token ผ่าน reCAPTCHA v3 ฝั่ง Client ไม่ปรากฏว่ากระทบผลลัพธ์ที่ผู้ใช้เห็นในทั้ง
  2 TC ที่ทดสอบ (หน้าจอยังทำงานและแสดงผลถูกต้อง) แต่ควรให้ผู้พัฒนาตรวจสอบต้นเหตุ (สาเหตุที่สงสัย
  — เป็นการคาดเดา: อาจเป็นเพราะ reCAPTCHA site key ไม่ตรง domain หรือ App Check ยังไม่ได้ตั้งค่า
  enforcement ให้ตรงกับโปรเจกต์ที่ deploy จริง)
- ฟีเจอร์ FR-17 (AI อธิบายผลการค้นหา) ทำงานและแสดงผลพร้อมป้ายกำกับ "ข้อมูลประกอบ ไม่ใช่คำแนะนำทาง
  การแพทย์" ในทั้ง 2 TC ที่ทดสอบ แต่ TC ที่เกี่ยวข้องกับ FR-17 โดยตรง (TC-03-11 ถึง TC-03-15) ไม่ได้อยู่
  ในขอบเขตที่ได้รับมอบหมายให้ทดสอบรอบนี้ ยังไม่ได้ตัดสินผลอย่างเป็นทางการ
- TC อื่นในไฟล์เดียวกัน (TC-03-01 ถึง TC-03-05, TC-03-08 ถึง TC-03-15) ไม่ได้อยู่ในขอบเขตงานที่ได้รับ
  มอบหมายรอบนี้ — ยังไม่ได้ทดสอบ
